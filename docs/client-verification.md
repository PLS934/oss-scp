2026-09-09, `bootstrap-react-client` 구현 결과입니다. 원격 CI 실행 결과가 아니라 로컬에서 실행한 검증 기록입니다.

## 실행 환경

- macOS 26.5.2 arm64, Node.js 24.19.0, pnpm 10.34.5
- Docker Desktop 4.86.0, Engine 29.7.2, Compose 5.3.1, 컨테이너 linux/arm64
- Playwright 1.63.0 Chromium
- CI는 Ubuntu 24.04 linux/amd64에 같은 검사를 구성했으며 아직 원격 실행하지 않았다.

검증 명령은 [클라이언트 개발 가이드](client-development.md#검증)에 정리했다. 새 체크아웃 검사는 기존 node_modules와 빌드 산출물을 제외한 임시 복사본에 설치부터 수행했다. Docker 검사 역시 임시 소스와 별도 프로젝트·볼륨을 사용하고 종료 후 정리했다.

## 검증 중 수정한 문제

- NestJS가 마운트된 dist 디렉터리 자체를 삭제하려다 발생하는 충돌: Docker 개발용 tsconfig에서 의존성 볼륨 아래 별도 출력 경로 사용.
- 최소 Node 이미지에 프로세스 조회 도구가 없어 watch 재시작 시 이전 서버가 남는 문제: 개발 이미지에 procps를 설치하고 실제 응답 변경으로 회귀 확인.
- 같은 웹 주소에서 배포→개발 전환 시 이전 정적 화면 캐시 사용: Nginx 정적 응답에 캐시 재검증을 지정하고 동일 브라우저에서 전환 후 HMR 확인.

## 검증 한계

별도의 물리 컴퓨터와 실제 사내 방화벽 조합에서는 실행하지 않았다. 대신 별도 Docker 네트워크의 클라이언트가 호스트 네트워크 IP를 호출해 포트 접근을 검증했다. Docker Desktop의 `host.docker.internal`은 호스트 loopback에도 접근 가능한 특수 경로라 개발 외부 접속 차단 검증 주소로 사용하지 않는다. 테스트 호스트에 여러 인터페이스가 있으면 `TEST_HOST_ADDRESS`로 검사할 IPv4 주소를 지정할 수 있다.

Windows·다른 브라우저·추가 OS/CPU·공개 레지스트리 배포는 미검증이며 이번 변경의 지원 완료로 주장하지 않는다. 원격 CI와 실제 설치 환경의 방화벽 허용은 별도로 확인한다.

## CI 이름 정리

워크플로를 `.github/workflows/integration-ci.yaml`, 표시 이름을 `서버·클라이언트 통합 검증`으로 변경했다. 기존 job·검사 명령이 동일함을 비교했고 문서 링크와 이전 경로 잔존 여부, OpenSpec 엄격 검증·변경 형식을 확인했다. 이름 변경에 따른 앱 테스트 재실행과 원격 CI 실행은 수행하지 않았다.
