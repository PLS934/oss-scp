# technical-preview-release Specification

## Purpose

0.1.0 개발 릴리스가 누구를 위한 어떤 수준의 기술 프리뷰인지, 무엇을 검증해야 공개할 수 있는지와 지원하지 않는 범위를 일관되게 판단하도록 한다.

## Requirements

### Requirement: 0.1.0 기술 프리뷰의 대상과 성격
프로젝트는 0.1.0을 외부 Registry에 접근할 수 없는 폐쇄망 단일 서버에서 평가·초기 도입하려는 운영자를 위한 기술 프리뷰로 SHALL 정의해야 한다. 0.1.0은 1.0.0 정식 릴리스의 운영 기능 전체나 장기 호환성·유지보수를 보장한다고 표시해서는 안 된다(MUST NOT).

#### Scenario: 기술 프리뷰 상태 확인
- **WHEN** 사용자가 README, 설치 문서 또는 0.1.0 릴리스 노트를 확인한다
- **THEN** 문서는 대상 환경, 기술 프리뷰 상태와 1.0.0 정식 릴리스가 아님을 일관되게 표시한다

### Requirement: 필수 사용자 여정
0.1.0은 오프라인 번들의 체크섬 검증과 이미지 load, 버전이 고정된 Compose 기동, 명시적 DB migration, 외부 플러그인·Connection 설정의 읽기 전용 주입과 사전 검증, 지원 원천 수집, 플랫폼 DB에 저장된 목록·상세 조회, 다음 테스트 버전으로의 업데이트와 실패 복구를 하나의 검증 가능한 사용자 여정으로 SHALL 제공해야 한다.

#### Scenario: 깨끗한 폐쇄망 서버의 최초 설치
- **WHEN** 운영자가 외부 Registry에 연결할 수 없는 깨끗한 지원 환경에서 0.1.0 번들과 별도 운영자 설정을 사용해 문서화된 설치 절차를 수행한다
- **THEN** 시스템은 소스 빌드 없이 기동되고 migration, health·ready, 대표 수집과 저장된 목록·상세 조회 검증을 통과한다

#### Scenario: 테스트 버전 간 업데이트와 복구
- **WHEN** 운영자가 문서화된 백업과 호환성 검사를 수행한 뒤 이전 테스트 버전에서 0.1.0으로 업데이트하거나 의도된 실패에서 복구한다
- **THEN** 외부 설정과 기존 데이터의 보존 여부, 적용 버전, 상태 검사 및 실패 단계에 맞는 롤백 또는 백업 복원 결과를 확인할 수 있다

### Requirement: 검증 대상 지원 환경
0.1.0은 Ubuntu 24.04 linux/amd64와 Docker Compose를 기준 배포 환경으로, PostgreSQL 17.6과 MySQL 8.4.6을 검증 대상 운영 DB로 SHALL 명시해야 한다. 자동 검증이나 문서화된 수동 검증을 수행하지 않은 OS, CPU 아키텍처, 컨테이너 런타임과 DB 버전을 지원한다고 주장해서는 안 된다(MUST NOT).

#### Scenario: 지원 환경 식별
- **WHEN** 운영자가 설치 전에 0.1.0 지원 범위를 확인한다
- **THEN** 문서는 검증한 OS·아키텍처·배포 방식·DB 제품과 버전 및 검증하지 않은 조합의 취급을 명확히 제공한다

### Requirement: 출시 차단 게이트
프로젝트는 GitHub issue #70, #71, #88, #89의 완료, 공개할 태그 커밋의 전체 CI 성공, 공개 산출물과 동일한 번들의 최초 설치·업데이트·복구 검증, 버전·digest·체크섬·알려진 제한 사항을 포함한 릴리스 노트를 0.1.0 공개의 필수 게이트로 SHALL 사용해야 한다. #71에서 태그 commit으로 검증한 개별 GitHub Release 자산은 #88 단일 오프라인 번들의 입력이어야 하며(MUST), `v0.1.0` GitHub Release는 기술 프리뷰 prerelease로 표시해야 한다(MUST). 하나라도 충족하지 않으면 v0.1.0 태그와 공개 릴리스를 생성해서는 안 된다(MUST NOT).

#### Scenario: 모든 게이트 통과
- **WHEN** 연결된 필수 이슈와 태그 후보 CI가 완료되고 개별 Release 자산 및 이를 사용한 최종 오프라인 번들 검증과 릴리스 문서 검토가 성공한다
- **THEN** 프로젝트는 검증한 커밋에 이동하지 않는 v0.1.0 태그를 붙여 GitHub prerelease로 기술 프리뷰를 공개할 수 있다

#### Scenario: 미완료 게이트 발견
- **WHEN** 연결 이슈, CI, 개별 자산, 최종 번들 검증 또는 필수 릴리스 정보 중 하나가 완료되지 않았다
- **THEN** 프로젝트는 0.1.0을 공개하지 않고 미완료 항목과 재검증 대상을 기록한다

### Requirement: 제외 기능과 알려진 제한 사항 공개
0.1.0 릴리스 문서는 LDAP·AD 인증, 역할 기반 접근 제어, 담당자·감사, 보관·삭제, 매일 22시 자동 수집, 검색·필터·정렬, 운영 상태 화면과 장기 호환성 보장이 지원 범위에 포함되지 않음을 SHALL 명시해야 한다. 문서는 현재 구현된 기능과 계획된 기능을 구분하고 제외 기능을 사용할 수 있는 것처럼 표현해서는 안 된다(MUST NOT).

#### Scenario: 제외 기능 확인
- **WHEN** 사용자가 0.1.0에서 계정관리나 자동 운영 기능을 평가한다
- **THEN** 릴리스 문서는 미지원 기능, 현재 가능한 대체 운영 절차와 후속 목표를 구분해 안내한다
