# plugin-transform-runtime Specification

## Purpose

수집된 원천 레코드를 플러그인이 선언한 플랫폼 레코드와 관계로 변환하고 공통 검증하여, 정상 결과만 DB 비종속 저장 경계로 전달하고 잘못된 레코드는 안전하게 격리한다.

## Requirements

### Requirement: 등록된 가공 모듈 로딩
플랫폼은 배포 전에 검증된 플러그인 디렉터리 안의 빌드된 JavaScript 가공 모듈만 SHALL 로딩해야 하며, 모듈이 이름이 고정된 `transform` 함수를 제공하는지 실행 전에 확인해야 한다. TypeScript 원본은 빌드 시 JavaScript로 변환해야 하며 런타임 문자열 평가는 허용하지 않아야 한다.

#### Scenario: 유효한 가공 모듈
- **WHEN** 등록된 플러그인이 플러그인 디렉터리 안의 빌드된 모듈에서 `transform` 함수를 제공한다
- **THEN** 플랫폼은 모듈을 한 번 로딩하고 이후 원천 레코드 처리에서 같은 함수를 재사용한다

#### Scenario: 잘못된 모듈 export
- **WHEN** 가공 모듈 로딩이 실패하거나 `transform` export가 함수가 아니다
- **THEN** 플랫폼은 원천 레코드를 처리하거나 저장 경계에 전달하지 않고 플러그인을 식별하는 실행 오류로 중단한다

### Requirement: 원천 레코드 단위 가공 계약
플랫폼은 원천 레코드 한 건마다 가공 함수를 순서대로 한 번 SHALL 호출해야 한다. 입력은 원천 레코드, 비밀정보가 없는 읽기 전용 실행 문맥과 취소 신호로 제한하고, 출력은 선언된 데이터 종류의 레코드 배열과 선택적 관계 배열이어야 한다. 한 입력 레코드는 레코드와 관계를 여러 개 반환할 수 있어야 한다.

#### Scenario: 하나의 원천에서 여러 결과 생성
- **WHEN** 가공 함수가 한 원천 레코드에서 여러 정규화 레코드와 그 관계를 반환한다
- **THEN** 플랫폼은 모든 출력을 같은 원천 레코드에 귀속해 검증한다

#### Scenario: 비동기 가공 완료 대기
- **WHEN** 가공 함수가 Promise를 반환한다
- **THEN** 플랫폼은 완료 또는 실패를 확인한 뒤에만 해당 원천 레코드의 다음 처리 단계로 진행한다

#### Scenario: 수집 방식과 DB에서 독립된 문맥
- **WHEN** JSON API 또는 CSV 경로가 동일한 원천 레코드 계약으로 가공 실행기를 호출한다
- **THEN** 가공 함수는 HTTP 응답 객체, NestJS 객체, 서비스 DB 세션, Connection 비밀과 checkpoint 없이 동일한 계약으로 실행된다

#### Scenario: sample2 최상위 메타데이터 접근
- **WHEN** sample2 source 계약이 레코드 배열 밖의 최상위 응답 정보를 가공 metadata로 허용한다
- **THEN** 각 원천 레코드의 가공 함수는 원본 응답 객체 전체나 비밀정보 없이 허용된 metadata를 읽을 수 있다

### Requirement: 가공 결과 공통 검증
플랫폼은 가공 결과를 저장 경계에 전달하기 전에 반환 구조, 선언된 데이터·관계 종류, 필수 필드, 필드 타입, 유일키, 관계 참조, 중첩 구조 및 건수·바이트 제한을 SHALL 검증해야 한다. 지원 타입은 string, number, boolean, datetime, object, array이며 datetime은 유효한 ISO 8601 문자열이어야 한다.

#### Scenario: 유효한 중첩 결과
- **WHEN** 가공 결과가 선언된 객체 내부 필드와 배열 요소 타입을 포함하고 모든 필수 필드와 유일키를 제공한다
- **THEN** 플랫폼은 중첩 값을 보존한 검증 완료 결과를 저장 경계에 제공한다

#### Scenario: sample2 중첩 객체와 배열 변환
- **WHEN** sample2 가공 코드가 원천의 중첩 객체와 객체 배열을 선언된 object·array 필드로 반환한다
- **THEN** 플랫폼은 선언된 하위 필드와 배열 요소를 재귀 검증하고 순서와 값을 보존한다

#### Scenario: CSV 문자열 업무 타입 변환
- **WHEN** CSV 가공 코드가 원천 문자열을 선언된 number, boolean 또는 datetime 값으로 변환한다
- **THEN** 플랫폼은 변환된 값을 각 업무 타입으로 검증하고 원천 문자열을 코어가 암묵적으로 변환하지 않는다

#### Scenario: 타입 또는 필수 필드 오류
- **WHEN** 결과 필드가 선언된 타입과 다르거나 필수 필드가 없다
- **THEN** 플랫폼은 오류 코드와 결과 필드 경로를 제공하고 해당 원천 레코드의 출력을 거부한다

#### Scenario: 비어 있거나 중복된 유일키
- **WHEN** 유일키가 없거나 비어 있거나 같은 처리 범위의 다른 결과와 중복된다
- **THEN** 플랫폼은 임의로 덮어쓰지 않고 해당 원천 레코드의 출력을 검증 실패로 격리한다

#### Scenario: 유효하지 않은 관계
- **WHEN** 관계 종류나 양 끝의 데이터 종류·키가 선언과 일치하지 않는다
- **THEN** 플랫폼은 해당 원천 레코드가 만든 레코드와 관계 전체를 저장 경계에서 제외한다

#### Scenario: 중첩 또는 크기 제한 초과
- **WHEN** 출력이 설정된 필드·레코드·관계 개수, 중첩 깊이, 배열 요소 수 또는 직렬화 바이트 제한을 초과한다
- **THEN** 플랫폼은 초과 종류를 식별하고 해당 원천 레코드의 출력 전체를 격리한다

### Requirement: 레코드 오류 격리와 부분 완료
플랫폼은 가공 예외, Promise 거부와 결과 검증 실패를 원천 레코드 단위로 SHALL 격리하고 가능한 나머지 레코드를 계속 처리해야 한다. 한 가공 호출의 출력 일부가 실패하면 그 호출의 출력 전체를 제외해야 하며 하나 이상의 격리 오류가 있으면 전체 성공이 아닌 `partial` 결과를 반환해야 한다.

#### Scenario: 한 레코드의 가공 예외
- **WHEN** 묶음의 한 원천 레코드에서 가공 함수가 예외를 던지고 다른 레코드는 정상이다
- **THEN** 플랫폼은 실패 레코드의 출력을 전달하지 않고 정상 레코드를 계속 처리하며 결과를 `partial`로 표시한다

#### Scenario: 출력 원자성 보존
- **WHEN** 한 원천 레코드가 만든 여러 레코드와 관계 중 하나가 검증에 실패한다
- **THEN** 플랫폼은 같은 호출에서 생성된 출력 전체를 제외하여 불완전한 관계를 저장 경계에 전달하지 않는다

#### Scenario: 비민감 오류 보고
- **WHEN** 원천 레코드가 격리된다
- **THEN** 오류는 플러그인 ID, 원천 순번, 안정적인 오류 코드, 결과 필드 경로와 비민감 메시지만 포함하고 원천 레코드 전체와 비밀정보를 포함하지 않는다

### Requirement: 취소와 실행 전체 오류
플랫폼은 가공 호출 전후에 취소 신호를 확인하고 취소 시 후속 레코드 처리를 SHALL 중단해야 한다. 모듈 로딩·정의 오류와 저장 소비자 실패처럼 계속할 수 없는 문제는 레코드 오류가 아닌 실행 전체 오류로 처리해야 한다.

#### Scenario: 레코드 사이의 취소
- **WHEN** 현재 비동기 가공이 끝난 뒤 취소 신호가 설정되어 있다
- **THEN** 플랫폼은 다음 원천 레코드를 호출하지 않고 취소 상태로 종료한다

#### Scenario: 저장 소비자 실패
- **WHEN** 검증된 결과를 받는 저장 소비자가 실패한다
- **THEN** 플랫폼은 후속 원천 레코드를 처리하지 않고 실행 전체 실패를 반환한다

### Requirement: 제한된 묶음과 처리 완료 대기
플랫폼은 검증된 결과를 제한된 묶음으로 저장 소비자에게 SHALL 전달하고 소비 완료를 기다린 뒤 다음 출력 처리를 계속해야 한다. 처리 완료된 전체 결과를 누적하지 않아야 하며 입력 전체 건수 증가만으로 메모리 사용량이 비례 증가하지 않아야 한다.

#### Scenario: 느린 저장 소비자
- **WHEN** 저장 소비자의 처리가 지연된다
- **THEN** 플랫폼은 제한을 넘는 후속 결과를 메모리에 누적하지 않고 소비 완료까지 다음 전달을 늦춘다

#### Scenario: 외부 자격증명 없는 세 샘플 가공
- **WHEN** 사용자가 저장소의 sample1·sample2 fixture와 로컬 CSV 샘플로 문서화된 가공 검증 명령을 실행한다
- **THEN** 외부 HTTP 수집기, DB와 자격증명 없이 세 플러그인의 선언된 타입 결과와 처리 상태를 확인할 수 있다

#### Scenario: 입력 형식에 독립적인 가공 실행
- **WHEN** offset JSON, single JSON과 CSV 원천 레코드가 각각의 플러그인 정의와 함께 가공 실행기로 전달된다
- **THEN** 플랫폼은 sample별 필드명·건수나 수집 방식을 코어에 추가하지 않고 같은 실행·검증·격리 경로를 사용한다
