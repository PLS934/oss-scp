# http-offset-collection Specification

## Purpose

검증된 설정만으로 JSON offset API를 제한된 묶음씩 안전하게 읽고, 후속 가공·저장 단계가 완료된 뒤에만 다음 묶음으로 진행할 수 있는 공통 수집 동작을 제공한다.

## Requirements

### Requirement: 설정 기반 offset 수집
수집기는 base URL, 상대 경로, HTTP 메서드, 목록·전체 건수 경로와 offset·limit 설정을 입력으로 받아 SHALL 업무 필드나 전체 건수를 코드에 고정하지 않고 JSON API를 수집해야 한다. 각 요청은 현재 offset과 설정된 limit을 사용하고 원천 레코드의 값과 순서를 변경하지 않아야 한다.

#### Scenario: sample1 네 묶음 수집
- **WHEN** sample1 수집기가 시작 offset 0과 limit 20으로 전체 72건을 수집한다
- **THEN** offset 0·20·40·60을 순서대로 요청하고 20·20·20·12건을 원본과 같은 값과 순서로 전달한다

#### Scenario: 다른 응답 경로의 API 수집
- **WHEN** 주소, 목록·전체 건수 경로와 전체 건수가 sample1과 다른 유효한 API 정의를 사용한다
- **THEN** 수집기는 코드 변경 없이 해당 설정의 경로에서 레코드와 전체 건수를 읽어 수집한다

#### Scenario: 정상 빈 원천
- **WHEN** 첫 응답의 전체 건수가 0이고 목록이 비어 있다
- **THEN** 처리 함수를 호출하거나 추가 요청을 하지 않고 0건 정상 완료한다

### Requirement: 묶음 단위 역압력과 제한된 보관
수집기는 SHALL 한 시점에 HTTP 요청과 처리 중인 묶음을 각각 최대 하나만 유지하고, 현재 묶음의 비동기 처리 함수가 성공한 뒤에만 다음 offset을 요청해야 한다. 처리 완료된 묶음이나 전체 레코드 목록을 수집 결과로 누적하지 않아야 한다.

#### Scenario: 느린 처리 완료 대기
- **WHEN** 첫 묶음의 처리 함수가 아직 완료되지 않았다
- **THEN** 수집기는 다음 offset 요청을 시작하지 않는다

#### Scenario: 다수 페이지의 제한된 메모리
- **WHEN** 같은 묶음 크기로 전체 페이지 수를 10배 늘린 실제 HTTP 수집을 Node.js 24의 격리된 측정 프로세스에서 실행한다
- **THEN** 강제 GC 후 측정한 peak heap 증가분은 작은 실행 대비 2배와 16 MiB 여유 중 큰 값을 넘지 않고 전달 건수와 요청 횟수만 증가한다

### Requirement: 전체 건수와 페이지 진행 검증
수집기는 SHALL 최초 응답의 `total`이 0 이상의 안전한 정수인지 검증하고, 이후 응답에서도 동일한 값인지 확인해야 한다. 각 페이지의 목록 길이는 현재 offset과 `total`로 기대되는 건수와 일치해야 하며, 누적 진행이 정확히 `total`에 도달한 경우에만 정상 완료해야 한다.

#### Scenario: 마지막 부분 묶음
- **WHEN** 남은 건수가 limit보다 작은 유효한 마지막 페이지를 받는다
- **THEN** 수집기는 남은 건수만 전달하고 추가 빈 페이지를 요청하지 않은 채 정상 완료한다

#### Scenario: 조기 빈 목록
- **WHEN** 현재 offset이 `total`보다 작은데 빈 목록을 받는다
- **THEN** 수집기는 불완전 응답 오류를 반환하고 이후 요청을 하지 않는다

#### Scenario: 페이지 건수 불일치
- **WHEN** 마지막 페이지가 아닌 응답의 목록 건수가 limit과 다르거나 마지막 응답의 건수가 남은 건수와 다르다
- **THEN** 수집기는 건수 불일치 오류를 반환하고 해당 묶음을 처리 함수에 전달하지 않는다

#### Scenario: 수집 중 total 변경
- **WHEN** 후속 페이지의 `total`이 첫 페이지의 값과 다르다
- **THEN** 수집기는 원천 변경 오류를 반환하고 해당 묶음과 이후 요청을 처리하지 않는다

### Requirement: 응답 구조와 바이트 한도
수집기는 SHALL 성공 응답의 압축 해제된 실제 본문을 읽는 동안 설정된 응답 바이트 한도를 적용하고, JSON 해석 후 각 레코드의 UTF-8 JSON 직렬화 크기에 단일 레코드 한도를 적용해야 한다. 목록 경로는 배열, 전체 건수 경로는 유효한 정수여야 하며 한 항목이라도 한도를 넘으면 해당 묶음 전체를 전달하지 않아야 한다.

#### Scenario: Content-Length 없는 큰 응답
- **WHEN** `Content-Length`가 없거나 한도 이내라고 표시됐지만 실제 수신한 압축 해제 본문이 응답 한도를 넘는다
- **THEN** 수집기는 읽기를 중단하고 크기 초과 오류를 반환하며 해당 묶음을 전달하지 않는다

#### Scenario: 압축 해제 후 한도 초과
- **WHEN** 압축된 전송 크기는 작지만 압축 해제된 본문이 응답 한도를 넘는다
- **THEN** 수집기는 압축 해제된 실제 바이트를 기준으로 응답을 거부한다

#### Scenario: 정상 레코드와 초과 레코드 혼합
- **WHEN** 한 페이지에 단일 레코드 한도 이내 항목과 초과 항목이 함께 있다
- **THEN** 수집기는 부분 목록을 전달하지 않고 해당 묶음 전체를 단일 레코드 크기 오류로 거부한다

#### Scenario: 잘못된 JSON 또는 응답 경로
- **WHEN** 성공 상태 응답이 유효한 JSON이 아니거나 설정된 목록·전체 건수 경로가 요구 타입과 다르다
- **THEN** 수집기는 응답 검증 오류를 반환하고 해당 묶음과 이후 요청을 처리하지 않는다

### Requirement: 실패와 취소 전파
수집기는 SHALL HTTP 비성공 상태, timeout, 호출자 취소와 처리 함수 실패를 구분 가능한 오류로 전달하고 이후 요청을 중단해야 한다. timeout과 취소 시 진행 중인 응답 읽기를 중단하고, 처리 함수에는 같은 취소 신호를 제공해야 하며 비밀정보나 응답 본문을 오류에 포함하지 않아야 한다.

#### Scenario: HTTP 오류
- **WHEN** 원천이 비성공 HTTP 상태를 반환한다
- **THEN** 수집기는 상태 코드와 요청 위치를 식별하는 HTTP 오류를 반환하되 응답 본문을 노출하지 않고 이후 요청을 하지 않는다

#### Scenario: timeout
- **WHEN** 연결 또는 응답 본문 수신이 설정된 timeout 안에 완료되지 않는다
- **THEN** 수집기는 진행 중인 요청을 중단하고 timeout 오류를 반환한다

#### Scenario: 외부 취소
- **WHEN** 호출자가 요청 또는 처리 도중 취소 신호를 보낸다
- **THEN** 수집기는 진행 중인 읽기와 후속 요청을 중단하고 취소 오류를 반환하며 처리 함수가 협력적으로 중단할 수 있도록 신호를 전달한다

#### Scenario: 처리 함수 실패
- **WHEN** 전달된 묶음의 처리 함수가 실패한다
- **THEN** 수집기는 처리 오류를 호출자에게 전파하고 다음 offset을 요청하지 않는다

### Requirement: 프레임워크 독립 실행과 검증 경로
HTTP offset 수집 기능은 SHALL NestJS 컨트롤러·HTTP 요청 객체·플랫폼 DB 세션 없이 Node.js 테스트나 후속 CLI에서 호출할 수 있어야 한다. 외부 자격증명 없는 mock API 통합 테스트와 문서화된 명령으로 정상·실패·자원 제한 동작을 검증해야 한다.

#### Scenario: 로컬 mock API 검증
- **WHEN** 사용자가 문서화된 workspace 테스트 명령을 실행한다
- **THEN** 테스트는 실제 loopback HTTP 서버에서 sample1 수집, 일반화된 다른 경로, 오류·timeout·취소·크기 제한과 역압력 동작을 외부 자격증명 없이 검증한다
