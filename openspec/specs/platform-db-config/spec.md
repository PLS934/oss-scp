# platform-db-config Specification

## Purpose

운영자가 입력한 플랫폼 DB 주소·포트·계정·비밀번호를 읽고 검사하여, 정상 입력은 프로그램이 사용할 설정으로 반환하고 잘못된 입력은 수정할 항목을 알려준다. 서버와 수집 CLI가 이 기능을 재사용한다.

이번 범위는 설정 검사와 DB별 연결 코드의 공통 규칙이다. 실제 DB 접속·계정 인증·테이블 생성은 후속 작업이며, 현재 서버 시작 과정에 이 검사 호출을 추가하지 않는다. 기존의 필수값·기본값·오류 처리 규칙은 아래 요구사항을 따른다.

## Requirements

### Requirement: 공통 접속 설정 검증
공통 설정 기능은 전달받은 환경변수에서 아래 설정을 읽고 검증해야 한다(SHALL). 설정 호출에는 완전한 DB 설정이 필요하며 누락을 DB 비활성화로 간주하지 않는다. 현재 health 서버에 이 호출을 연결하는 것은 후속 DB 연결 작업의 책임이다.

| 변수 | 규칙 |
|---|---|
| PLATFORM_DB_TYPE | 필수, 등록 어댑터 ID. 초기 제품 ID는 postgres/mysql |
| PLATFORM_DB_HOST | 필수, 공백뿐인 값·앞뒤 공백·제어문자·URL 형태 거부 |
| PLATFORM_DB_PORT | 미설정 시 등록 어댑터 기본 포트, 지정 시 십진 정수 1~65535 |
| PLATFORM_DB_NAME / PLATFORM_DB_USER | 필수, 빈 값·공백뿐인 값·앞뒤 공백·제어문자 거부 |
| PLATFORM_DB_POOL_MAX | 기본 10, 십진 정수 1~100 |
| PLATFORM_DB_CONNECT_TIMEOUT_MS | 기본 5000, 십진 정수 1~60000, 연결 확보 한도 |
| PLATFORM_DB_TLS_MODE | 기본 verify-full, disable 또는 verify-full |
| PLATFORM_DB_TLS_CA_FILE | 선택, verify-full에서만 허용, 읽을 수 있는 비어 있지 않은 UTF-8 PEM 인증서 파일 |

숫자 설정의 빈 문자열·소수·지수·부호·공백은 거부해야 한다(SHALL). 파일 경로는 실행 작업 디렉터리에 따라 달라지지 않도록 절대 경로만 허용한다. 이 설정을 사용자 요청·원천 Connection에서 읽거나 브라우저에 전달하지 않아야 한다(SHALL).

#### Scenario: 등록된 제품의 기본 설정
- **WHEN** 필수값과 비밀번호를 전달하고 선택값을 생략한다
- **THEN** 등록된 기본 포트와 위 기본값이 적용된 설정을 반환한다

#### Scenario: 포트에 문자를 입력
- **WHEN** 등록된 DB의 나머지 필수 설정은 올바르지만 `PLATFORM_DB_PORT=abc`를 전달한다
- **THEN** `PLATFORM_DB_PORT`와 정수 범위 규칙을 알리는 설정 오류를 반환하며 DB 접속을 시도하지 않는다

#### Scenario: 잘못된 접속 설정
- **WHEN** 필수값 누락, 잘못된 포트 또는 제한값, 미지원 TLS 모드를 전달한다
- **THEN** 해당 설정 이름과 고정된 오류 코드로 거부하고 입력값은 오류에 포함하지 않는다

### Requirement: 비밀번호 전달 방식
설정 기능은 PLATFORM_DB_PASSWORD와 PLATFORM_DB_PASSWORD_FILE 중 정확히 하나를 받아야 한다(SHALL). 빈 문자열을 포함해 두 변수가 모두 지정되면 거부한다. 직접 값의 공백은 보존한다. 파일은 일반 파일 또는 일반 파일을 가리키는 심볼릭 링크를 허용하며 UTF-8로 읽고 마지막 LF 또는 CRLF 한 개만 제거한다. 그 외 공백은 보존하고 남은 CR/LF, NUL, 빈 값, 잘못된 UTF-8 및 16 KiB 초과 파일은 거부해야 한다(SHALL). 직접 값에도 빈 값·CR/LF·NUL 및 UTF-8 기준 16 KiB 크기 제한을 적용한다.

#### Scenario: 파일 비밀번호
- **WHEN** 끝에 CRLF 하나가 있는 비밀번호 파일을 전달한다
- **THEN** 해당 줄바꿈만 제거한 비밀번호를 반환하고 앞뒤 공백은 유지한다

#### Scenario: 비밀번호 설정 실패
- **WHEN** 두 방식 동시 지정, 둘 다 누락, 읽기 실패, 상대 경로 또는 잘못된 파일 내용을 전달한다
- **THEN** 설정을 거부하고 파일 내용·입력 경로·원본 파일 시스템 오류를 외부 오류에 포함하지 않는다

### Requirement: TLS 검증 계약
verify-full은 인증서 체인과 접속 호스트명을 모두 검증하는 연결 계약이어야 한다(SHALL). CA 파일이 없으면 실행 환경의 기본 신뢰 저장소를 사용한다. disable과 CA 파일의 동시 설정은 거부하며 암호화 또는 인증서 검증 실패를 평문 연결로 자동 전환하지 않아야 한다(SHALL). 파일 파서는 PEM 인증서 형식을 확인하며 실제 서버 인증서 검증은 후속 어댑터 연결 시 수행한다. CA 파일은 UTF-8, 일반 파일 또는 그 심볼릭 링크, 최대 1 MiB로 제한한다.

#### Scenario: 사설 CA 사용
- **WHEN** verify-full과 유효한 CA 인증서 파일을 전달한다
- **THEN** 호스트 검증을 유지한 TLS 설정을 어댑터에 전달할 수 있다

#### Scenario: 모순된 TLS 설정
- **WHEN** disable과 CA 파일을 함께 지정하거나 잘못된 PEM 파일을 전달한다
- **THEN** 고정된 설정 오류로 거부한다

### Requirement: 등록 어댑터와 연결 수명주기 경계
공통 기능은 빌드에 포함해 호출자가 전달한 등록 목록만 사용해야 한다(SHALL). 어댑터 등록은 고유 ID·계약 버전 1·기본 포트·연결 factory를 갖추어야 하고, 중복 ID·잘못된 포트·미지원 버전·factory 누락은 거부한다. 연결 결과는 준비 상태 검사와 종료 기능을 제공해야 한다(SHALL). 환경변수 값으로 모듈을 동적 import하거나 경로를 실행하지 않는다. 이 단계에는 postgres/mysql 실제 어댑터를 등록하지 않는다.

#### Scenario: 미등록 DB 선택
- **WHEN** 등록 목록에 없는 DB를 선택한다
- **THEN** 연결 factory와 비밀번호 파일 읽기를 수행하기 전에 거부한다

#### Scenario: 공통 계약 재사용
- **WHEN** 서버 또는 CLI와 동일한 설정 경계를 사용하는 테스트 소비자가 유효한 테스트 어댑터를 전달한다
- **THEN** 같은 설정 결과로 연결·준비 상태 확인·종료 계약을 사용할 수 있고 NestJS나 원천 Connection이 필요하지 않다

### Requirement: 단계별 실행 호환성과 오류 공개
이 변경은 기존 DB 없는 health 실행과 응답을 유지해야 한다(SHALL). 설정 검증 성공을 실제 연결 성공으로 표시하지 않는다. 후속 서버 연결은 잘못된 설정과 최초 연결 실패를 시작 실패로 처리하고, 실행 중 DB 장애는 readiness 실패로 표시하며 liveness와 구분해야 한다(SHALL). 이 변경은 후속 계약을 문서화하며 HTTP readiness 구현은 포함하지 않는다. 공통 오류는 코드·설정 이름·고정 문구만 공개해야 한다(SHALL).

#### Scenario: 외부 자격증명 없는 기존 실행
- **WHEN** DB 설정 없이 기존 health 서버와 mock 샘플을 실행한다
- **THEN** 기존 실행과 health 응답을 유지하고 새 DB 접속을 시도하지 않는다

#### Scenario: 오류의 비밀정보 제외
- **WHEN** 설정 또는 파일 오류에 비밀번호와 경로를 포함한 테스트 입력을 사용한다
- **THEN** 오류 메시지·직렬화·로그 출력에 해당 값이나 원본 오류가 노출되지 않는다
