- [x] 1.2 런타임 메뉴의 list.query 메타데이터와 웹 메뉴 검증을 추가하고 선언 순서·최소 공개 정보·서버 전용 정보 제외 및 기존 columns 형식 보존 테스트로 확인한다.

## 2. 조건 정규화와 cursor

- [x] 2.2 v2 cursor에 조건·선언 지문을 결합하고 조건 변경 거부, 동등한 조건 순서 허용, v1 무조건 조회 호환, cursor 크기 제한 테스트를 통과시킨다.

## 3. 서버와 DB 조회

- [x] 3.1 1·2 이후 API의 q/filters 파싱과 registry 기반 허용 조건 검증을 구현하고 정상 조합, 직접 우회, 반복 인자, 미등록 활성 조건, malformed JSON, DB 접근 전 400 및 503 비밀정보 제외 API 테스트를 통과시킨다.
- [x] 3.2 PostgreSQL에서 검증된 조건을 WHERE에 적용하고 바인딩·타입 보호·날짜 변환·정렬 이전 검색 및 기존 수집 상태/요약 한도 계약을 DB 테스트로 확인한다.
- [x] 3.3 MySQL에도 동일 조건 계약을 구현하고 동일 fixture로 Unicode·대소문자·특수문자·공백·null·잘못된 타입·숫자·날짜 경계 결과가 PostgreSQL과 일치함을 확인한다.
- [x] 3.4 첫 무조건 묶음 밖의 일치 결과, 여러 조건부 묶음, 동일 시각 경계, 마지막 묶음과 응답 크기 제한을 양쪽 실제 DB에서 검증하고 대표 데이터의 EXPLAIN·소요 시간을 기록한다.

## 4. 공통 표 상호작용

- [x] 4.1 웹 records 클라이언트의 q/filters 직렬화·타입·오류 처리를 확장하고 특수문자와 다중 조건 전달 및 기존 요청 호환 테스트를 통과시킨다.
- [x] 4.2 선언 기반 검색창·선택형·숫자/UTC 날짜 범위 입력, 적용/Enter와 미적용 안내를 구현하고 미정의 항목 미표시·키보드 입력·잘못된 범위 방지 화면 테스트를 통과시킨다.
- [x] 4.3 적용 조건을 목록 sessionKey에 결합하고 번호형 1페이지 재시작·초기화·메뉴 전환·오래된 응답 무시·조회 중 이전 결과 제거·동일 조건 재시도 테스트를 통과시킨다.
- [x] 4.4 결과 없음/수집 전/부분 완료/실패 상태 안내를 구분하고 활성 조건의 빈 결과와 수집 상태가 함께 표시됨을 화면 테스트로 확인한다.
- [x] 4.5 개별 필터 입력을 표의 필터 가능 컬럼 헤더 팝오버로 이동하고, 검색창 아래 draft 조건 배지와 개별 삭제를 구현한다. 선언 없는 컬럼 유지, 네 가지 필터 종류, 한쪽 범위, 적용 전 결과 유지, 팝오버 viewport 배치, 바깥 클릭·Esc, 데스크톱·모바일 및 PostgreSQL/MySQL 통합 시나리오를 검증한다.
- [x] 4.6 공통 적용·초기화 버튼과 미적용 안내를 제거한다. 컬럼 필터 변경·배지 삭제·검색 지우기는 즉시 적용하고, 검색은 무테 원형 화살표 버튼 또는 Enter로 확정한다. 검색 입력값과 적용값 분리, 빈 검색 재적용, 잘못된 범위의 요청 차단·복구, 첫 페이지 이동, 요청 경합을 화면 및 PostgreSQL/MySQL 통합 테스트로 검증한다.
