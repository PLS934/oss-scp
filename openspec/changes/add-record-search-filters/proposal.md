## Why

보안팀과 개발팀은 현재 수집된 목록을 묶음 단위로 넘기며 원하는 데이터를 찾아야 한다. 전체 저장 데이터에 검색과 필터를 함께 적용해 필요한 취약점과 관리 대상을 빠르게 확인한다.

## What Changes

- 플러그인 필드에 검색 허용 여부와 명시적 필터 종류·정적 옵션을 추가한다.
- 공통 표에 단일 검색창, 선택값·숫자 범위·날짜 범위 필터, 적용·초기화와 결과 없음 안내를 제공한다.
- 서버가 지정 필드 OR 검색과 필터 AND 조합을 수행하고 PostgreSQL/MySQL 모두 묶음 분할 전에 조건을 적용한다.
- 검색·필터 조건을 cursor에 귀속하고 조건 변경 시 첫 묶음으로 이동한다.
- 제외 범위: 사용자 정렬, 개인 설정 저장, 동적 옵션 조회, 중첩 객체·배열 검색, 전문 검색, 새 인증·권한 체계. 0.1.0 릴리스 지원 범위는 별도로 변경하지 않는다.

## Capabilities

### New Capabilities

- `record-search-filters`: 플러그인 검색·필터 선언, API 검증, DB 조건 적용, cursor 귀속과 공통 표의 상호작용을 규정한다.

### Modified Capabilities

없음. 기존 조건 없는 목록 계약은 유지하고 선택적인 검색·필터 계약을 별도 기능으로 추가한다.

## Impact

`packages/plugin-config`, `apps/api`, `packages/platform-db`, `apps/web` 및 샘플 플러그인에 영향을 준다. 기존 GET `/api/v1/records`에 선택적 질의 인자를 추가하고 메뉴 응답에 검색·필터 메타데이터를 제공한다. 기존 플러그인의 선언 생략을 허용한다. 관련 단위·API·양쪽 실제 DB·화면 검증과 플러그인/클라이언트/서버 문서를 갱신한다.
