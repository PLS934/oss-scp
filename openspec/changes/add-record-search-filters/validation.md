## 조회 계획과 측정

1,000건 중 `Alpha`와 점수 9 이상을 만족하는 45건을 조회하는 fixture를 사용했다. limit 20의 cursor 목록 전체 호출(메타데이터 조회 포함)을 단일 측정했다. 로컬 반복 실행에서 PostgreSQL은 약 2.5~4.6ms, MySQL은 약 7.5~8.1ms였으며 두 DB 모두 기존 `platform_records_cursor_index`를 사용하는 계획을 확인했다. MySQL 계획은 filesort 없이 인덱스 순서로 읽었다. JSON 검색 조건은 인덱스 내 후보 행을 읽으며 평가하므로 운영 데이터 크기에서 재측정해야 한다. 이 측정은 운영 성능 보장이 아니다.

재현 명령은 `pnpm test:browser:search`이며 원본 EXPLAIN·소요 시간은 `test-results/record-search-both.json` 또는 DB별 JSON으로 생성된다. CI의 MySQL·PostgreSQL 작업에 같은 브라우저 검증과 측정 결과 artifact 업로드를 추가했다.

## 컬럼 헤더 필터 UI

개별 필터 입력을 필터가 선언된 표 컬럼 헤더의 팝오버로 이동하고, 검색창 아래에 draft 조건 배지와 개별 삭제를 추가했다. 필터 미선언 컬럼은 일반 헤더로 유지하며 빈 결과에서도 헤더를 남겨 조건을 다시 편집할 수 있다. 팝오버는 body portal과 viewport 좌표 보정으로 표의 가로 스크롤에 잘리지 않게 했다.

웹 테스트 123개, 웹 타입 검사, 전체 lint·build, OpenSpec strict 검증을 통과했다. `node scripts/test-record-search.mjs`를 통해 선택형·다중 선택·숫자·날짜 필터, 한쪽 범위, 적용 전 결과 유지, 조건 배지·개별 삭제, 바깥 클릭·Esc, 데스크톱·모바일 viewport 배치와 기존 서버 72건·저장소 153건을 PostgreSQL 17.6 및 MySQL 8.4.6에서 검증했다.

## 검색 확정과 필터 즉시 적용

공통 적용·초기화 버튼과 미적용 안내를 제거했다. 검색 입력값과 적용값을 분리해 화살표 버튼 또는 Enter에서만 검색을 확정하며, 값이 있을 때만 표시되는 X는 검색 조건을 즉시 지운다. 컬럼 필터 변경과 조건 배지 삭제는 즉시 조회에 반영한다. 숫자·날짜 범위가 잘못된 동안에는 요청을 보내지 않고 마지막 성공 결과와 표 헤더를 유지하며, 값을 고치면 즉시 다시 조회한다.

웹 테스트 123개, 웹 타입 검사, 전체 lint·build를 통과했다. 읽기 전용 기존 데이터에서 서버 자산 72건과 저장소 153건을 확인했고, `node scripts/test-record-search.mjs`로 검색 확정·검색 지우기·필터 즉시 적용·개별 삭제·잘못된 범위 차단과 복구·첫 페이지 이동·요청 경합을 PostgreSQL 17.6과 MySQL 8.4.6에서 검증했다. 모바일 viewport에서 컬럼 팝오버 배치도 다시 확인했다.
