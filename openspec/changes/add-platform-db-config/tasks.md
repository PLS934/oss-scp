이번 작업은 DB 접속 정보를 읽고 검사하는 공통 기능을 구현한다. 정상 입력은 설정을 반환하고 오류 입력은 고칠 항목을 알려주는지 테스트한다. 실제 DB 연결·테이블 생성과 서버 시작 과정에 검사 호출을 연결하는 일은 #27 이후에 진행한다.

## 1. 접속 정보와 비밀번호 읽기·검사

- [x] 1.1 최신 main의 독립 작업 브랜치에 이 change를 옮기고 `@oss-scp/platform-db` 패키지·TypeScript 선언·Vitest 설정·잠금 파일을 구성한다. 기존 미커밋 작업을 보존하고 frozen-lockfile 설치와 패키지 빌드로 확인한다.
- [x] 1.2 환경변수 파서와 공통 오류를 구현한다. 필수값, 제품별 등록 기본 포트, 숫자 범위·형식, 비어 있는 선택값의 실패를 단위 테스트로 검증한다.
- [x] 1.3 비밀번호 값/파일의 상호 배타 규칙과 크기 제한 파일 읽기를 구현한다. LF/CRLF·공백 보존·UTF-8·빈 값·NUL·상대 경로·읽기 실패·디렉터리·심볼릭 링크를 임시 파일 테스트로 확인한다.
- [x] 1.4 TLS 모드와 CA 파일 검증을 구현한다. 기본 verify-full, 명시적 disable, CA와 disable 충돌, 유효/잘못된 PEM·크기 초과·읽기 실패를 테스트한다.

## 2. DB별 연결 코드가 따를 규칙과 기존 서버 호환성

- [x] 2.1 버전 1의 어댑터 등록·선택 검증과 연결/준비 상태/종료 타입을 구현한다. 중복·미등록 ID, 잘못된 버전·포트·factory와 비밀번호 읽기 전 거부를 가짜 어댑터 테스트로 확인한다.
- [x] 2.2 서버/CLI 소비 예제를 테스트에 작성해 프레임워크와 원천 Connection 없이 동일 계약을 사용함을 검증한다. 실제 DB 성공으로 오인시키는 기본 어댑터는 등록하지 않는다.
- [x] 2.3 오류 메시지·직렬화·표준 로그 표현에 테스트 비밀번호·경로·원본 오류가 포함되지 않는지 회귀 테스트한다. 기존 API health 테스트가 그대로 통과함을 확인한다.

## 3. 문서와 통합 검증

- [x] 3.1 `.env.example`에 비밀정보 없는 주석 예시와 `docs/platform-db.md` 설정 표·서버 가이드 링크를 추가한다. 직접 비밀번호/파일, 로컬 TLS disable/운영 verify-full, 현재 설정 파서만 제공하고 실제 연결은 #27·#28이라는 설명을 문서와 대조한다. 설정 입력 → 정상 반환/포트 오류/비밀번호 중복·파일 오류 예시가 설계와 명세에 일치하는지 확인한다.
- [x] 3.2 깨끗한 설치에서 문서의 패키지 검사 명령을 실행하고 기존 GitHub Actions의 재귀 검사에 신규 패키지가 포함되는지 확인한다. `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`와 OpenSpec strict 검증 결과를 기록한다. 실제 DB·Docker 연결 검증은 후속 범위임을 명시한다.

## 검증 결과

- 2026-09-10, macOS arm64, Node.js 24.20.0, pnpm 10.34.5의 신규 worktree에서 frozen-lockfile 설치 성공.
- `pnpm typecheck`, `pnpm lint`, `pnpm test`(전체 158개, 신규 82개), `pnpm build` 통과. 파일 오류 정리 수정 후 신규 패키지 테스트·빌드, 전체 타입 검사·린트 재통과.
- `openspec validate add-platform-db-config --strict`, `git diff --check` 통과.
- 기존 Actions 재귀 검사에 신규 패키지가 포함됨을 확인. 원격 CI는 아직 실행하지 않음.
- 실제 DB·Docker 연결 및 Windows 검증은 수행하지 않음. 실제 DB 연결은 #27·#28의 범위.
