## Why

플랫폼을 설치하는 운영자는 사용할 DB의 주소·포트·DB 이름·계정·비밀번호를 입력해야 한다. 이번 #26은 이 입력을 읽고 검사하여, 올바르면 다음 연결 단계에서 사용할 설정을 반환하고 잘못되면 고쳐야 할 항목을 알려주는 기능을 만든다.

예를 들어 포트에 `abc`를 입력하면 포트 설정 오류를 반환하고, 비밀번호 파일을 지정하면 그 파일에서 비밀번호를 읽는다. PostgreSQL과 MySQL이 같은 검사 기능을 사용하도록 준비하는 단계다.

## What Changes

- 운영자가 전달한 DB 종류·주소·포트·이름·계정 설정의 필수값과 형식을 검사한다.
- 비밀번호는 직접 입력하거나 파일에서 읽는다. 두 방식을 동시에 지정하면 어느 값을 사용할지 임의로 고르지 않고 오류를 반환한다.
- 암호화 연결(TLS) 설정과 연결 수·대기 시간 제한을 검사한다.
- 오류에는 수정할 설정 이름과 이유를 제공하고 비밀번호는 포함하지 않는다.
- 서버와 명령줄 수집 프로그램(CLI)이 같은 검사 기능을 재사용하도록 공통 패키지와 DB별 연결 코드의 인터페이스를 제공한다. 인터페이스는 후속 코드가 따라야 할 규칙이다.

이번 작업의 완료 결과는 **설정 검사 함수·자동화 테스트·설정 예시·문서**다. 독립된 설정 입력 화면이나 검사 명령을 만드는 작업은 아니다. 현재 서버는 이 함수를 아직 호출하지 않으므로 `.env`에 DB 항목을 적는 것만으로 이번 단계에서 DB 연결이 시작되지는 않는다.

| 작업 | 담당 이슈 |
|---|---|
| 접속 설정 읽기·검사, 비밀번호 파일 읽기 | 이번 #26 |
| 실제 PostgreSQL 접속 및 함께 설치 | #27 |
| 실제 MySQL 접속 및 함께 설치 | #28 |
| 업무 테이블 생성·데이터 저장·조회 | #29~#31 |

현재 DB 없이 실행하는 서버 상태 확인(health) 기능은 유지한다. 원천 수집·인증 기능도 이번 범위에 포함하지 않는다.

## Capabilities

### New Capabilities

- `platform-db-config`: 운영자가 입력한 DB 접속 정보·비밀번호·TLS 설정을 검사하고 DB별 연결 코드가 사용할 공통 규칙을 제공한다.

### Modified Capabilities

없음. 기존 health 및 원천 Connection 계약은 변경하지 않는다.

## Impact

신규 `packages/platform-db`, pnpm 잠금 파일, 주석 처리한 `.env.example` 예시, `docs/platform-db.md` 및 서버 가이드 링크가 대상이다. 기존 workspace 재귀 빌드·테스트·타입 검사와 GitHub Actions에 통합한다. DB 제품이나 외부 자격증명을 이 단계의 실행 의존성으로 추가하지 않는다.

관련 이슈: #26, 상위 #25. 구현 브랜치는 최신 main에서 분리하며 현재 다른 작업의 미커밋 변경은 보존한다.
