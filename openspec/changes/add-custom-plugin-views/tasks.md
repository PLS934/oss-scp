## 1. 사용자 정의 화면 계약과 선택

- [ ] 1.1 목록·상세 컴포넌트 props와 플러그인 ID 기반 정적 registry 타입을 추가하고, 목록·상세의 독립 등록 및 미등록 조회를 타입 검사와 단위 테스트로 확인한다.
- [ ] 1.2 메뉴 route에서 화면 종류별 사용자 정의 컴포넌트 또는 기존 공통 화면을 선택하도록 연결하고, 메뉴 이동·직접 URL·새로고침 및 목록/상세 개별 fallback을 라우팅 테스트로 확인한다.

## 2. 오류 격리와 샘플 화면

- [ ] 2.1 사용자 정의 route 영역에 오류 경계를 추가하고 렌더링 실패 안내, shell·메뉴 유지와 다른 route 이동 시 복구를 화면 테스트로 확인한다.
- [ ] 2.2 샘플 플러그인 하나의 사용자 정의 목록을 공개 메뉴 context와 조회 클라이언트로 구현하고, 사용자 정의 목록에서 공통 상세로 이동하는 통합 화면 테스트를 통과시킨다.

## 3. 문서와 전체 검증

- [ ] 3.1 플러그인 개발 문서에 정적 등록 방법, 목록·상세 props, 미등록 fallback, API·권한 경계, 오류 처리와 플랫폼 웹 재빌드 제약을 기록하고 구현 계약과 대조한다.
- [ ] 3.2 웹 테스트·lint·typecheck·빌드를 실행하고 기존 플러그인의 공통 목록·상세 회귀와 외부 UI 번들을 로드하지 않는 배포 경계를 확인한다.
