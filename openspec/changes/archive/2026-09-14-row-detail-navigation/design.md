## Context

`RecordListView`는 semantic table과 각 행 끝 `Link`를 렌더링한다. URL은 `recordDetailPath(menu.path, item.id)`로 생성하며 기존 Vitest는 정적 HTML의 href를, `scripts/test-browser.mjs`는 `보기` 링크 클릭을 검증한다. 현재 컬럼은 scalar 표시값만 지원한다. 접근성과 유효한 표 구조를 함께 유지할 방법을 정하기 위해 설계를 작성한다. 동기는 proposal.md를 따른다.

## Goals / Non-Goals

**Goals:** 유효한 표 구조와 네이티브 링크의 Enter·새 탭 열기 의미를 유지하면서 한 행에 하나의 Tab 정지점과 전체 행 클릭 영역을 제공한다.

**Non-Goals:** 행 선택 상태, 격자 키보드 탐색, 다중 선택, 새 API, 페이징 로직, 테마 선택 UI를 만들지 않는다.

## Decisions

- `tr`의 row 의미를 링크 역할로 덮거나 `a`로 `tr`을 감싸지 않는다. 첫 번째 셀의 표시값을 기존 React Router `Link`로 감싸고, 행의 나머지 비대화형 영역 클릭은 그 링크를 통해 동일 경로로 이동시킨다. 링크 자체 클릭은 브라우저 기본 동작을 보존하고 행 핸들러가 중복 실행하지 않는다. 대안인 셀마다 링크 추가는 보조 기술에 같은 대상이 반복되므로 채택하지 않는다.
- 첫 셀 링크만 Tab 정지점이 된다. 사용자가 행에 포커스한 것으로 인지하도록 `:focus-within`으로 전체 행을 강조한다. 네이티브 링크가 Enter를 처리하므로 수동 키보드 이벤트를 중복 구현하지 않는다. 행 전체 클릭 영역은 각 셀의 여백도 포함한다.
- 접근 가능한 링크 이름은 메뉴 제목, 첫 컬럼의 기존 formatter 표시값, 내부 UUID와 `상세`를 조합한다. UUID로 누락·중복 표시값에서도 대상을 구분한다. JSX 텍스트/속성으로 전달하며 외부 값을 HTML로 해석하지 않는다. 선언하지 않은 필드는 참조하지 않는다.
- 행 hover/focus 스타일은 전용 클래스 아래에 둔다. 기존 색상 체계와 명확한 outline을 사용하며 #74 테마 변경과 통합 시 같은 상태가 양쪽 테마에서 보이는지 검증한다.
- 원천 조회, 레코드 식별·갱신, 담당자 지정, 상세 API 오류 처리는 기존 구현을 유지한다. 페이지 이동 실패로 남아 있는 성공 목록도 같은 행 상세 이동을 제공한다.

## Risks / Trade-offs

- 첫 셀 링크 이외 영역은 링크의 브라우저 컨텍스트 메뉴를 직접 제공하지 않는다 → 네이티브 링크에서 새 탭 열기와 주소 복사가 가능하며 이슈의 일반 클릭·Enter 기준을 만족시킨다. 행 클릭은 텍스트 선택 중에는 이동하지 않도록 방어한다.
- hover/focus가 가로 스크롤 표에서 잘릴 수 있다 → outline 또는 셀 경계 강조를 안쪽에 적용하고 브라우저에서 첫·마지막 셀과 셀 여백을 검증한다.
- #86과 renderer·browser test, #74와 CSS 충돌 가능 → 본 변경은 행과 링크 테스트에 한정하고 통합 후 세 동작을 다시 확인한다.

## Migration Plan

DB migration이나 API 동시 배포 없이 웹 산출물만 갱신한다. 기존 CI의 웹 단위 검사와 브라우저 smoke에 회귀 검증을 포함한다. 문제가 있으면 #87 변경을 되돌려 기존 상세 열을 복구할 수 있다.
