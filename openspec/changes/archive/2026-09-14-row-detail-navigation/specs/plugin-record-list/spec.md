## MODIFIED Requirements

### Requirement: 목록 레코드에서 공통 상세로 이동한다
기본 목록은 별도 `상세` 액션 열과 `보기` 링크 없이 각 데이터 행 전체를 상세 이동 대상으로 제공해야 한다(SHALL). 각 저장 레코드의 플랫폼 내부 UUID를 같은 메뉴의 상세 경로에만 SHALL 사용해야 하며, 외부 원천의 `externalKey`를 route 식별자로 사용하지 않아야 한다(MUST NOT). 목록을 조회하는 보안팀과 개발팀 사용자에게 동일한 탐색 동작을 제공하며 기존 조회 범위를 변경하지 않아야 한다(MUST). 각 행은 Tab으로 접근할 수 있는 상세 링크와 Enter 활성화를 제공하고, 보조 기술에 링크 의미와 해당 레코드의 상세 이동 대상을 전달해야 한다(SHALL). 마우스 hover와 키보드 focus 상태는 행 전체에서 시각적으로 구별되어야 한다(MUST).

#### Scenario: 목록 행 상세 이동
- **WHEN** 사용자가 데이터 행의 어느 셀이나 그 여백을 클릭한다
- **THEN** 현재 메뉴 경로와 해당 레코드 내부 UUID로 생성한 상세 URL로 이동한다
- **AND** 목록에는 별도 `상세` 액션 열과 `보기` 링크가 표시되지 않는다

#### Scenario: 키보드와 보조 기술 접근
- **WHEN** 사용자가 Tab으로 데이터 행의 상세 링크에 접근한다
- **THEN** 행마다 하나의 Tab 정지점에서 행 전체의 focus 상태가 보인다
- **AND** 보조 기술은 링크와 레코드를 식별하는 상세 이동 대상 이름을 전달한다
- **AND** Enter를 누르면 클릭과 동일한 상세 URL로 이동한다

#### Scenario: 행 hover 표시
- **WHEN** 포인터가 데이터 행의 어느 셀 위에 놓인다
- **THEN** 행 전체의 hover 상태와 클릭 가능함을 나타내는 포인터를 표시한다

#### Scenario: 표시 값이 없거나 중복된 레코드
- **WHEN** 레코드의 표시 값이 누락되거나 다른 레코드와 같다
- **THEN** 링크의 접근 가능한 이름은 내부 UUID를 포함해 대상을 구별하고 URL도 해당 내부 UUID를 사용한다
- **AND** 선언하지 않은 원천 필드는 이름에 추가하지 않는다

#### Scenario: 데이터 없는 상태
- **WHEN** 최초 로딩, 빈 결과 또는 조회 실패로 표시할 저장 레코드가 없다
- **THEN** 가상의 상세 이동 행이나 링크를 생성하지 않고 기존 상태 안내를 유지한다

#### Scenario: 상세에서 목록 복귀
- **WHEN** 사용자가 목록 복귀 동작을 선택한다
- **THEN** 같은 플러그인의 등록 메뉴 경로로 이동한다
