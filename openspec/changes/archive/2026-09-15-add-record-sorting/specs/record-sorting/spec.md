## Purpose

플러그인이 허용한 목록 필드를 사용자가 한 번에 하나씩 정렬하고 현재 방향을 확인하며 검색·필터·번호형 페이지와 일관되게 결합할 수 있게 한다.

## ADDED Requirements

### Requirement: 전체 건수 옆에서 단일 정렬을 선택한다
화면은 전체 건수 옆에 플러그인이 정렬 가능으로 선언한 목록 필드의 뱃지를 선언 순서대로 SHALL 표시해야 한다. 같은 뱃지를 누르면 해제, 오름차순, 내림차순 상태를 `오름차순 → 내림차순 → 해제` 순서로 순환해야 한다. 다른 뱃지를 누르면 기존 정렬을 해제하고 새 필드의 오름차순만 적용해야 한다.

#### Scenario: 같은 뱃지의 상태 순환
- **WHEN** 사용자가 해제 상태의 정렬 뱃지를 세 번 누른다
- **THEN** 요청 정렬은 차례로 해당 필드 오름차순, 내림차순, 사용자 정렬 없음이 되고 뱃지는 현재 상태를 시각적·접근성 이름으로 표시한다

#### Scenario: 다른 정렬 필드 선택
- **WHEN** 한 필드가 내림차순인 상태에서 다른 정렬 뱃지를 누른다
- **THEN** 기존 필드 정렬은 해제되고 새 필드의 오름차순 정렬 하나만 적용된다

#### Scenario: 미선언 컬럼
- **WHEN** 목록 컬럼에 정렬 가능 선언이 없다
- **THEN** 화면은 해당 컬럼의 정렬 뱃지를 만들지 않는다

### Requirement: 정렬을 조회 조건과 결합한다
정렬 변경은 현재 검색·필터 및 페이지 크기를 유지하고 cursor 이력이나 번호형 페이지 위치를 폐기한 뒤 첫 페이지를 SHALL 즉시 조회해야 한다. 메뉴 변경은 정렬을 해제해야 하며 늦게 도착한 이전 정렬 응답을 표시하지 않아야 한다.

#### Scenario: 검색·필터 결과 정렬
- **WHEN** 두 번째 페이지에서 검색·필터가 활성화된 채 정렬을 변경한다
- **THEN** 같은 검색·필터와 새 정렬로 첫 페이지를 조회하고 전체 건수는 유지한다

#### Scenario: 정렬 요청 경합
- **WHEN** 이전 방향의 요청보다 새 정렬 요청이 먼저 완료된다
- **THEN** 화면은 새 정렬 결과만 표시한다
