## 2. 시작 화면과 로컬 연결

- [x] 2.1 한국어 시작 화면과 접근 가능한 연결 상태 영역, 실패 시 새로고침 안내를 구현한다. Playwright로 화면 제목과 로딩·성공·실패 텍스트를 확인한다.
- [x] 2.2 5초 제한 시간과 취소 정리를 포함한 상태 확인을 구현한다. Vitest로 정상 응답, 비정상 HTTP, 콘텐츠 유형·JSON·status 오류, 네트워크 오류, 무응답 제한 시간, 취소된 요청의 상태 덮어쓰기 방지를 검증한다.
- [x] 2.3 Vite 동일 출처 `/api` 프록시와 `API_PROXY_TARGET`, 기본 포트 5173 및 충돌 시 실패를 구성한다. 실제 API와의 성공·서버 부재 실패·없는 API의 404, 사용자 지정 프록시 주소와 포트 충돌을 검증한다.
- [x] 2.4 임시 프로젝트 복사본에서 소스 텍스트를 변경하는 Playwright HMR 검사를 추가한다. 열린 페이지의 document 교체·수동 새로고침·서버 재시작 없이 변경이 반영되고 임시 파일·프로세스가 정리되는지 확인한다.

## 3. Docker 실행

- [x] 3.1 멀티 스테이지 웹 Dockerfile과 최소 빌드 입력 허용 목록을 추가한다. 호스트 Node.js 설치에 의존하지 않고 이미지가 빌드되며 최종 이미지에 소스·환경 비밀정보·개발 도구가 포함되지 않는지 확인한다.
- [x] 3.2 Nginx 정적 제공, 실행 시 `API_UPSTREAM` 치환, 런타임 DNS 해석과 정적 healthcheck를 구성한다. API가 없는 상태에서도 웹 이미지 단독 기동과 정적 화면 제공이 성공하는지 확인한다.
- [x] 3.3 Compose 웹 서비스와 `WEB_PORT`를 추가한다. 기존 API 포트·healthcheck를 유지하고 통합 빌드·기동, 브라우저 연결 성공, 프록시 경로·API 404 보존을 검증한다.
- [x] 3.4 별도 Compose 프로젝트에서 API 중단·재생성 후 실패·복구를 검증한다. 같은 웹 이미지로 다른 upstream 설정을 적용해 재빌드 없는 연결 변경과 정적 화면 지속 제공을 확인하고 테스트 자원을 정리한다.

- [x] 3.5 클라이언트 Vite·서버 NestJS watch를 실행하는 `compose.yaml`에 함께 적용할 `compose.dev.yaml`과 소스 연결·분리된 의존성 볼륨을 추가한다. `docker compose -f compose.yaml -f compose.dev.yaml config`로 병합된 포트·명령·환경변수·healthcheck를 검토하고, 같은 파일 조합의 `up --build`로 기동하여 호스트 Node.js·pnpm 없이 실제 API 연결이 성공하는지 확인한다.
- [x] 3.6 임시 복사본에서 Docker 실행 중 화면·서버 코드를 수정하는 자동화 검사를 추가한다. 이미지 재빌드·컨테이너 재생성 없이 HMR과 서버 자동 재시작이 반영되고 브라우저 document가 유지되는지 확인한다. 의존성 갱신·재기동·자원 정리도 검증한다.

## 4. CI와 문서 검증

- [x] 4.1 GitHub Actions에 웹 타입 검사·린트·Vitest·빌드와 Playwright 브라우저 설치·화면·로컬 및 Docker HMR·서버 watch·Docker 통합 검사를 연결한다. 기존 서버 테스트·프로세스·Docker 검증이 유지되고 실패가 CI 실패로 전달되는지 확인한다.
- [x] 4.2 README와 클라이언트 개발 가이드, 관련 서버 문서 및 비밀정보 없는 환경변수 예시를 갱신한다. 설치·두 터미널 로컬 개발·Docker 개발 기동 및 의존성 갱신·검사·이미지 단독 실행·Compose 실행·종료·정리 명령과 OS·CPU 검증 범위, 이번 단계에 샘플 초기화가 없음을 명시하고 링크와 CI 명령의 일치를 확인한다.
- [x] 4.3 새 임시 체크아웃에서 문서만 따라 frozen 설치·로컬 개발·HMR·검사와 Docker 빌드·통합 브라우저 확인을 수행한다. 실행 환경·명령·결과와 미검증 항목을 기록하고 이슈 완료 조건 8개를 아래 대응표로 최종 대조한다.

- [x] 4.4 개발 플랜과 openspec/config.yaml에 반영한 Docker 개발·다른 컴퓨터 접속 계획을 실제 구현과 대조한다. 기존 미커밋 변경을 보존하면서 README·서버 가이드·명세·설계 사이의 실행 방식에 모순이 없는지 확인한다.

- [x] 4.5 배포 웹 포트의 외부 공개와 로컬·Docker 개발 웹 포트의 loopback 제한을 자동 검사한다. 개발 Compose 병합 결과에 외부 공개 매핑이 남지 않는지 확인한다. 별도 컴퓨터 또는 격리된 네트워크 클라이언트에서 배포 화면·API 연결 성공과 개발 웹 포트 접근 불가를 검증한다. HMR은 실행 컴퓨터에서 검증한다. 별도 컴퓨터 검증을 못 했다면 대체 검증 범위와 한계를 명시한다.

- [x] 4.6 CI 파일을 integration-ci.yaml로, Actions 표시 이름을 서버·클라이언트 통합 검증으로 변경한다. 관련 문서 링크를 갱신하고 검사 명령·job 보존, 이전 경로 참조 누락, OpenSpec 엄격 검증을 확인한다.
