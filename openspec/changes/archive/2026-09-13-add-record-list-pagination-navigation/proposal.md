## Why

플러그인 기본 목록은 다음 cursor로만 이동할 수 있어 여러 묶음의 저장 데이터를 탐색한 사용자가 직전 결과로 돌아가거나 현재 위치를 파악하기 어렵다. 보안 운영자가 화면 조회 범위와 묶음 크기를 안정적으로 제어할 수 있도록 cursor 기반 계약 위에 양방향 탐색 상태를 제공해야 한다.

## What Changes

- 방문한 cursor 이력을 사용해 기본 목록에서 이전·다음 묶음으로 이동하고 현재 묶음 위치를 표시한다.
- 첫 묶음과 마지막 묶음, 로딩·빈 결과·오류 상태에 맞춰 탐색 컨트롤을 일관되게 활성화하거나 비활성화한다.
- 20·50·100·200건의 묶음 크기 선택을 조회 요청에 반영하고, 크기 또는 route context 변경 시 cursor 이력과 위치를 초기화한다.
- 이동 중 이전 요청을 취소하고 늦은 응답을 무시해 최신 목록 상태가 덮어써지지 않게 한다.
- 키보드와 스크린 리더로 탐색 및 묶음 크기 컨트롤을 사용할 수 있게 한다.
- 단위 테스트와 브라우저 테스트로 양방향 이동, 마지막 묶음, 크기·route 변경, 요청 경합을 검증한다.
- 개인 목록 설정을 통한 묶음 크기 영속 저장과 임의 페이지 번호 이동은 이번 변경에서 제외한다.

## Capabilities

### New Capabilities

- 없음.

### Modified Capabilities

- `plugin-record-list`: 기존 순방향 cursor 목록을 방문 이력 기반 이전·다음 탐색, 현재 위치, 묶음 크기 초기화 및 안전한 요청 경합 처리까지 확장한다.

## Impact

- 클라이언트 목록 상태와 UI: `apps/web/src/record-list.tsx`, 관련 스타일
- 단위 및 브라우저 검증: `apps/web/test/record-list.test.tsx`, `scripts/test-browser.mjs`
- 조회 API 계약은 변경하지 않으며 기존 `cursor`, `limit`, `pageInfo`를 그대로 사용한다.
- 새 런타임 의존성이나 서버 변경은 없다.
