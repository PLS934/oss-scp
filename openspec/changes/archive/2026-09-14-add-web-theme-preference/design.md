## Context

동기는 proposal.md를 따른다. 현재 `main.tsx`는 React 셸을 즉시 렌더링하며 `index.html`에는 테마 초기화가 없다. `App.tsx`의 상단 공통 헤더는 경로와 무관하게 존재한다. `style.css`에는 페이지·상단 공통 헤더·표·상세·상태 색상 리터럴이 고정되어 있다. Vitest는 `apps/web/test`에서 실행하고 실제 브라우저 검증은 Playwright를 사용하는 `scripts/test-browser.mjs`가 담당한다. 기존 테마 capability는 없다.

## Goals / Non-Goals

**Goals:** 초기화와 실행 중 선택에 동일한 결정 규칙을 적용하고 조회 컴포넌트에 테마 분기를 넣지 않는다. 현재 React StrictMode에서도 구독이 중복되거나 누수되지 않게 한다.

**Non-Goals:** 서버 선호 동기화, 외부 수집 데이터 변환, 계정별 저장, 새 UI 라이브러리 도입, 탭 간 즉시 동기화는 포함하지 않는다. API·DB·담당자 지정과 수집 계약은 변경하지 않는다.

## Decisions

1. 선택값은 `system | light | dark`, 실제 적용값은 `light | dark`로 구분한다. 저장 키는 `oss-scp.theme`로 제안한다. 저장값을 허용 목록으로 검증하며 저장소 예외를 처리하고 시스템 조회 불가 시 라이트로 폴백한다. 테마 변경은 메모리 상태와 문서에 먼저 적용하고 저장을 시도해 저장 실패가 조작을 막지 않게 한다. 계정 저장 대안은 현재 인증과 무관한 범위에 불필요하다.
2. `index.html`의 head에 작은 동기 초기화 스크립트를 두고 스타일 및 앱 첫 렌더 이전에 `document.documentElement.dataset.theme`과 `color-scheme`을 설정한다. React effect만 사용하는 대안은 첫 표시에서 잘못된 색상이 보일 수 있다. 런타임의 테마 모듈은 동일한 검증·해석 규칙을 사용하며 초기 스크립트와의 동작 일치를 테스트한다. 초기화 코드는 외부 값 실행이나 HTML 삽입 없이 허용된 두 값만 적용한다.
3. 상단 헤더의 태양·달 아이콘 버튼은 현재 테마의 반대로 직접 전환한다. 저장된 값이 없을 때 시스템 설정을 따르고 직접 전환하면 명시적 선택을 저장한다. matchMedia 변경은 시스템 기본 모드에서만 실제 테마와 아이콘을 갱신한다.
4. CSS custom properties를 페이지/표면/텍스트/보조 텍스트/경계/상단 공통 헤더/활성·hover/성공·실패/안내·오류/컨트롤/포커스 의미별로 정의한다. 루트의 실제 테마 속성에서 값을 전환하고 기존 클래스가 토큰을 사용하게 한다. 상세 값·목록 상태까지 전수 적용하고 네이티브 컨트롤은 `color-scheme`과 명시적 전경·배경을 함께 쓴다. 화면별 조건부 클래스를 늘리는 대안은 플러그인 정의 기반 화면과의 일관성을 떨어뜨린다.
5. Vitest에서 선택 결정·손상 값·저장 예외·구독 cleanup을 검증하고 Playwright에서 키보드 선택, 라우트 이동 후 유지, 새로고침·재방문, OS 변경 및 명시 모드 고정을 검증한다. 첫 표시 검증은 앱 모듈 로딩을 지연해 초기 문서 테마·배경을 확인한 다음 앱 렌더 결과와 비교한다. 토큰의 실제 사용 배경 조합별 대비를 계산하고 두 테마의 주요 화면도 확인한다. 기존 브라우저 테스트 도구를 재사용한다.

## Risks / Trade-offs

- [초기 스크립트와 런타임 결정 규칙 불일치] → 같은 입력 행렬을 두 경로에 적용하는 회귀 검증을 둔다.
- [고정 색상 누락과 부적절한 상태색] → CSS 색상 사용 전체를 감사하고 실제 전경/배경 쌍의 대비를 측정한다.
- [저장소 제한 환경에서 재방문 유지 불가] → 현재 세션의 조작은 유지하고 문서에 저장 범위를 설명한다.
- [#86·#87과 CSS 및 브라우저 테스트 충돌] → 각 PR은 최신 main에서 독립 검증한다. 통합 시 두 이슈가 추가한 상태·hover·포커스에도 의미 토큰 적용 여부를 확인한다. 기능 로직을 이 PR에 포함하지 않는다.

## Migration Plan

서버나 DB migration 없이 웹 정적 자산을 빌드·배포한다. 기존 저장값이 없으므로 최초 방문은 시스템 설정을 따른다. 롤백은 이전 웹 자산으로 가능하며 남은 브라우저 키는 이전 버전이 사용하지 않는다. 개발·배포 빌드 모두에서 초기 스크립트 실행을 검증한다.



사용자 검토 반영: 서버 연결 상태와 제품 버전도 상단 헤더 오른쪽으로 이동하고 테마 버튼과 함께 표시한다. 상태 색상은 헤더 배경을 기준으로 대비를 검증한다.

최종 사용자 결정: 저장된 선택이 없으면 시스템 테마를 따른다. 태양 버튼을 누르면 다크(달), 달 버튼을 누르면 라이트(태양)로 즉시 전환하고 명시적 선택을 저장한다. 팝오버와 시스템 설정 선택 UI는 제공하지 않는다. 버튼은 전환 대상 이름을 보조 기술에 제공하며 Enter·Space로 조작한다.
