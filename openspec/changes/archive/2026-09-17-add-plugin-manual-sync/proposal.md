## Why

플러그인을 추가하거나 설정을 바꾼 직후 보안 운영자가 정기 실행이나 서버 재시작, CLI 사용을 기다리지 않고 해당 플러그인의 최신 데이터를 확인할 수 있어야 한다. 현재 목록 화면은 저장 데이터와 수집 상태만 조회할 수 있어, 운영자가 같은 화면에서 안전하게 전체 동기화를 요청하고 결과까지 확인하는 흐름이 필요하다.

## What Changes

- 각 플러그인 데이터 목록 화면에 해당 플러그인의 활성 수집 대상 전체를 실행하는 `지금 동기화` 동작과 실행 범위 안내를 추가한다.
- 수동 동기화를 비동기로 접수하는 API를 추가하고 `202 Accepted` 응답에 요청 식별자를 제공한다.
- 실행 중 중복 요청을 클라이언트와 서버에서 차단하고, 기존 수동 CLI·기동 수집과 같은 수집 코어 및 DB 실행 조정 계약을 재사용한다.
- 실행 중과 성공·부분 성공·실패 결과, 마지막 성공 시각 및 실행 불가 이유를 목록 화면에 표시하고 완료 뒤 첫 목록을 다시 조회한다.
- 계정관리가 비활성화된 현재 배포 모드에서는 실행을 허용하되, 향후 인증 활성화 시 `collection:execute` 권한을 적용할 수 있는 서버 권한 경계를 둔다.
- 비활성 플러그인, 활성 수집 대상 없음, 중복 실행, 실행 실패에 대해 안정된 공개 오류 코드와 비밀정보 없는 안내를 제공한다.
- 실패 또는 부분 실패에서도 기존 저장 데이터와 플랫폼이 관리하는 수동 업무 데이터를 보존한다.
- 모든 플러그인을 한 번에 실행하는 전역 동기화, 실행 취소·재시도 큐, 정기 실행, 새 인증 제공자나 운영 토큰 도입은 포함하지 않는다.

## Capabilities

### New Capabilities

- `plugin-manual-sync`: 플러그인별 수동 전체 동기화 요청 API, 실행 권한 경계, 실행 가능성·상태·결과 및 목록 갱신 계약을 정의한다.

### Modified Capabilities

- `collection-run-coordination`: 수동 UI/API trigger가 기동·CLI 실행과 동일한 대상 실행권 및 오래된 결과 보호 계약에 참여하도록 확장한다.
- `plugin-record-list`: 목록 화면에 동기화 범위, 실행 동작, 실행 불가 이유, 결과와 마지막 성공 시각을 표시하고 완료 후 목록을 갱신하도록 확장한다.

## Impact

- `apps/api`: 수동 동기화 controller, 요청 검증·권한 경계·비동기 실행 관리자와 상태 응답이 추가된다.
- `apps/web`: 수동 동기화 API 클라이언트, 목록 화면 상태·polling·완료 후 첫 페이지 갱신 및 접근성 테스트가 추가된다.
- `apps/collector-cli` 및 `packages/collection-engine`: CLI와 API가 공유할 실행 조립 경계를 분리하되 기존 collector·runner 동작은 유지한다.
- `packages/platform-db`: PostgreSQL·MySQL의 실행 상태 조회와 중복 실행 참조에 필요한 공통 조회 계약이 확장될 수 있으며 기존 레코드·담당자 데이터는 변경하지 않는다.
- API 및 클라이언트 문서와 자동화 테스트가 갱신된다. 새로운 외부 서비스 의존성이나 breaking API 변경은 없다.
