## Why

운영자는 등록된 플러그인이 어떤 원천과 데이터 계약, 변환 코드, 화면 구성을 사용하는지 현재 웹 화면에서 한 번에 확인할 수 없다. 플러그인 편집 기능을 도입하기 전에 플랫폼이 실제로 로드한 구성을 비밀정보 노출이나 실행 상태 변경 없이 점검할 수 있는 읽기 전용 상세 화면이 필요하다.

## What Changes

- 등록된 플러그인의 식별 정보, 수집 설정과 한도, 데이터 타입·중첩 필드·관계, 메뉴·목록·상세 구성을 반환하는 읽기 전용 API를 추가한다.
- 플랫폼이 로드한 transform 파일을 등록된 플러그인 범위 안에서만 읽고, TypeScript 원본 또는 배포 JavaScript 여부와 조회 실패 사유를 함께 반환한다.
- 플러그인 목록에서 설정 상세 화면으로 이동하고 섹션별 구성을 읽기 전용으로 표시한다.
- 없는 플러그인, 상세 조회 실패, transform 파일 조회 실패를 서로 구분해 표시한다.
- connection의 인증 참조와 비밀 값, 내부 절대 경로는 응답에서 제외하고 조회 요청이 파일·registry·수집 실행 상태를 변경하지 않도록 한다.
- 플러그인 생성·수정·삭제, 파일 쓰기, registry 변경, 재시작·재적용, 수동 수집 실행은 포함하지 않는다.

## Capabilities

### New Capabilities

- `plugin-config-detail`: 등록된 플러그인의 로드된 구성과 transform 코드를 안전하게 조회하고 웹에서 읽기 전용으로 표시하는 동작을 정의한다.

### Modified Capabilities

- `plugin-home`: 플러그인 목록의 각 항목에서 해당 플러그인 설정 상세 화면으로 진입하는 동작을 추가한다.

## Impact

- `packages/plugin-config`: 브라우저에 노출 가능한 상세 응답 계약과 로드된 구성의 안전한 투영을 추가한다.
- `apps/api`: 플러그인 상세 조회와 제한된 transform 파일 읽기 API, 오류 처리를 추가한다.
- `apps/web`: 상세 응답 검증, 라우팅, 읽기 전용 상세 UI와 상태 표시를 추가한다.
- API 응답에는 비밀 값이나 내부 파일 경로를 포함하지 않으며 기존 플러그인 목록·레코드 조회 계약은 유지한다.
