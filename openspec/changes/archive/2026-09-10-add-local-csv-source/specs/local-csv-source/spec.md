## Purpose

등록된 플러그인이 플랫폼 실행 환경의 로컬 CSV 파일을 안전하게 읽어 원천 문자열 행을 제한된 묶음으로 전달하고, 완전한 순회만 성공으로 판정하게 한다.

## ADDED Requirements

### Requirement: 로컬 CSV source 선언
플랫폼은 source 계약 버전, `local-csv` 형식, 설정 루트 기준 상대 파일 경로, 묶음 크기와 선택적 파일·레코드 크기 한도를 선언할 수 있게 SHALL 제공해야 한다. 로컬 CSV source는 HTTP Connection을 요구하거나 허용하지 않아야 하며 숫자·날짜·불리언 업무 타입 변환을 수행하지 않아야 한다.

#### Scenario: 유효한 상대 파일 source
- **WHEN** 운영자가 설정 루트 안의 CSV 파일과 유효한 묶음·크기 한도를 선언한다
- **THEN** 플랫폼은 파일의 절대 위치와 실행 옵션을 포함한 로컬 CSV 수집 정의를 생성한다

#### Scenario: 설정 루트 밖 파일
- **WHEN** source가 절대 경로나 상위 경로 이동으로 설정 루트 밖 파일을 참조한다
- **THEN** 플랫폼은 파일을 열지 않고 해당 경로 설정을 거부한다

#### Scenario: 로컬 source의 Connection 지정
- **WHEN** 로컬 CSV source가 HTTP Connection 참조 또는 요청 속성을 포함한다
- **THEN** 플랫폼은 허용되지 않은 형식별 속성으로 설정을 거부한다

### Requirement: 제한된 CSV 행 묶음 전달
플랫폼은 공통 CSV 파서가 반환한 행을 전체 파일에 비례하는 메모리를 사용하지 않고 설정된 최대 행 수의 묶음으로 SHALL 전달해야 한다. 각 값은 문자열 표기와 순서를 보존해야 하며 source 계약에 샘플 전용 필드 이름을 고정하지 않아야 한다.

#### Scenario: 등록된 취약점 CSV 샘플
- **WHEN** 등록된 샘플 플러그인으로 `fixtures/csv/vulnerabilities.csv`를 실행한다
- **THEN** 플랫폼은 53행과 각 행의 6개 필드를 중복·누락 없이 묶음으로 전달하고 `10.0`, `0.10`을 문자열로 유지한다

#### Scenario: 다른 구조의 CSV
- **WHEN** 헤더와 행 수가 다른 유효한 CSV를 새 플러그인 설정으로 실행한다
- **THEN** 플랫폼은 코어 변경 없이 그 헤더를 키로 사용하는 문자열 행 묶음을 전달한다

#### Scenario: 느린 묶음 소비
- **WHEN** 수집 소비자가 다음 묶음 처리를 늦춘다
- **THEN** 플랫폼은 소비 속도에 맞춰 파일 읽기를 제한하고 전체 파일을 미리 메모리에 적재하지 않는다

### Requirement: 완료·실패·취소 구분
플랫폼은 파일을 끝까지 읽고 변경 없음이 검증된 경우에만 로컬 CSV 수집 범위를 완료로 SHALL 표시해야 한다. 설정 오류, 파일 없음, 접근·읽기 실패, CSV 형식 오류, 파일 변경, 크기 초과와 취소를 구분해야 하며 실패 또는 취소 시 파일 자원을 해제하고 전체 성공을 표시하지 않아야 한다.

#### Scenario: 정상 완료
- **WHEN** 유효한 CSV 파일의 모든 행과 마지막 묶음이 소비되고 완료 검증이 성공한다
- **THEN** 마지막 전달 결과만 해당 로컬 파일 범위가 완전하게 수집되었음을 표시한다

#### Scenario: 파일 또는 형식 실패
- **WHEN** 파일 접근, 읽기, 파싱, 변경 감지 또는 한도 검사에서 오류가 발생한다
- **THEN** 플랫폼은 원인별 오류를 반환하고 어떤 부분 묶음도 전체 완료의 근거로 표시하지 않는다

#### Scenario: 실행 취소
- **WHEN** 묶음 전달 전후 또는 파일 순회 중 취소 신호가 확인된다
- **THEN** 플랫폼은 취소 오류로 종료하고 파일 자원을 해제하며 전체 완료를 표시하지 않는다
