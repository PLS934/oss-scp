## 1. 저장 계약과 입력 검증

- [ ] 1.1 DB 드라이버 타입을 노출하지 않는 실행·범위·레코드·관계·격리 오류·checkpoint 저장 타입과 `RecordStorage` 인터페이스를 추가하고 TypeScript 빌드로 공개 계약을 검증한다.
- [ ] 1.2 외부 키 타입 보존 및 canonical 변환, JSON 직렬화 크기, 문자열 길이와 묶음 내 중복 검증을 구현하고 string/number 충돌·`-0`·비유한 숫자·크기 초과 단위 테스트를 통과시킨다.
- [ ] 1.3 저장 오류를 안정된 오류 코드로 정의하고 드라이버 상세 및 비밀정보가 노출되지 않는 단위 테스트를 통과시킨다.

## 2. PostgreSQL 스키마와 구현

- [ ] 2.1 공통 레코드·관계·수집 실행·checkpoint·격리 오류 테이블, 외래 키, 유일 제약과 필요한 공통 조회 인덱스를 additive PostgreSQL migration으로 추가하고 기존 migration 재실행 테스트를 통과시킨다.
- [ ] 2.2 PostgreSQL 실행 시작·종료 및 checkpoint 조회를 구현하고 실행 범위·상태 전이·집계 동작을 실제 PostgreSQL에서 검증한다.
- [ ] 2.3 레코드 upsert와 타입 보존 범위 식별을 구현하고 재전달 시 내부 ID 유지·원천 값 갱신 및 다른 범위의 동일 키 구분을 실제 PostgreSQL에서 검증한다.
- [ ] 2.4 관계 끝점 해석과 idempotent upsert를 구현하고 같은 묶음·기존 레코드 참조, 재전달, 누락 끝점 오류를 실제 PostgreSQL에서 검증한다.
- [ ] 2.5 레코드·관계·격리 오류·checkpoint·실행 집계를 단일 트랜잭션으로 확정하고 시작 checkpoint 충돌과 저장 실패가 전체 rollback되는지 실제 PostgreSQL에서 검증한다.

## 3. 공통 계약 검증과 문서

- [ ] 3.1 재시도 후 누락 없는 결과, partial 실행의 격리 오류 근거·집계, 플랫폼 소유 대표 연결 정보 보존을 포함한 재사용 가능한 저장 계약 테스트를 작성하고 PostgreSQL adapter에 통과시킨다.
- [ ] 3.2 `packages/platform-db`의 빌드·단위·PostgreSQL 통합 테스트와 저장소 전체 lint를 실행해 변경 범위의 회귀가 없음을 확인한다.
- [ ] 3.3 공통 저장 모델, 키 범위, 크기 제한, 트랜잭션 및 원천/플랫폼 소유 경계와 현재 제외 범위를 개발 문서에 설명하고 문서 링크를 확인한다.
