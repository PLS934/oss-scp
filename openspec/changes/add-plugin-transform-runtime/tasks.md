## 1. 플러그인 데이터 정의 계약

- [x] 1.1 실패하는 설정 테스트로 `transform`, 데이터 종류, 재귀 필드 타입, 필수 여부, 유일키와 관계 정의의 정상·오류 사례를 추가하고 테스트가 새 요구사항 때문에 실패하는지 확인한다.
- [x] 1.2 plugin JSON Schema와 공개 설정 타입에 가공·데이터 정의를 구현하고 `pnpm --filter @oss-scp/plugin-config test`로 구조 검증을 확인한다.
- [x] 1.3 설정 로더에 가공 모듈 상대 경로·확장자·파일 존재와 유일키·관계 교차 참조 검증을 추가하고 경로 이탈·누락·잘못된 참조 테스트를 통과시킨다.
- [x] 1.4 내부 수집 정의에 안전하게 해석된 가공 모듈과 데이터 정의를 포함하고 기존 offset·single 로더 회귀 테스트를 통과시킨다.

## 2. 공개 가공 SDK

- [x] 2.1 `packages/plugin-sdk` workspace 패키지와 TransformInput·TransformOutput·레코드·관계 타입을 추가하고 타입 전용 패키지 빌드가 성공하는지 확인한다.
- [x] 2.2 읽기 전용 문맥에 plugin/source 식별자, 수집 시각, 제한된 metadata와 AbortSignal만 노출하는 타입 검사를 추가하고 DB·NestJS·Connection 비밀 의존성이 없는지 빌드 결과로 확인한다.

## 3. 모듈 로딩과 결과 검증

- [x] 3.1 `packages/collection-engine` 패키지에 동적 import 가공 로더의 실패 테스트를 먼저 추가하고 정상 export, 잘못된 export, import 실패와 경로별 캐시를 구현해 통과시킨다.
- [x] 3.2 데이터 정의별 검증기를 생성해 반환 구조, 알 수 없는 데이터·필드, 필수 필드, string·number·boolean·datetime 타입을 검사하고 각 오류 코드·경로 테스트를 통과시킨다.
- [x] 3.3 object·array 재귀 검증과 중첩 깊이 8·배열 요소 1,000개·출력 JSON 1 MiB 제한을 구현하고 정상 경계값 및 초과 테스트를 통과시킨다.
- [x] 3.4 원천 호출당 레코드 100개·관계 200개 제한, 유일키 존재·허용 타입·비어 있지 않은 값·처리 범위 중복과 관계 끝점 검증을 구현하고 원자적 거부 테스트를 통과시킨다.

## 4. 레코드 단위 가공 실행

- [x] 4.1 원천 레코드를 순서대로 동기·비동기 transform에 전달하고 호출 완료를 기다리는 실행기를 테스트 우선으로 구현한다.
- [x] 4.2 가공 예외·Promise 거부·검증 실패 시 해당 호출 출력 전체를 격리하고 정상 레코드를 계속 처리해 `partial` 상태와 비민감 구조화 오류를 반환하는 테스트를 통과시킨다.
- [x] 4.3 호출 전후 AbortSignal을 확인해 취소 후 다음 레코드를 실행하지 않고, 모듈 로딩·정의 오류를 전체 실패로 구분하는 테스트를 통과시킨다.
- [x] 4.4 검증 결과를 레코드 100개 또는 1 MiB 이하 묶음으로 비동기 소비자에게 전달하고 완료를 기다리며 소비자 실패 시 중단하는 backpressure 테스트를 통과시킨다.
- [x] 4.5 고정 입력 묶음을 반복한 메모리·처리 시간 검증으로 전체 처리 건수에 비례한 결과 누적이 없음을 확인하고 측정 기준과 결과를 기록한다.

## 5. 세 샘플 통합과 문서

- [x] 5.1 sample1·sample2 fixture와 CSV 샘플의 실제 필드를 확인해 세 플러그인을 필수 데이터 정의와 TypeScript transform 계약으로 함께 갱신하고 빌드된 JavaScript 모듈이 생성되는지 확인한다.
- [x] 5.2 sample1 가공 코드가 기본 필드 매핑과 선언 타입을 반환하는지, sample별 필드명이나 72건을 코어에 고정하지 않는 통합 테스트로 확인한다.
- [x] 5.3 sample2 가공 코드가 중첩 객체·객체 배열을 보존하고 source 계약이 허용한 최상위 응답 metadata에 원본 응답 전체 없이 접근하는지 fixture 통합 테스트로 확인한다.
- [x] 5.4 CSV 가공 코드가 원천 문자열을 명시적으로 number·boolean·datetime으로 변환하고 공통 엔진이 암묵적 타입 변환을 하지 않는지 로컬 CSV 통합 테스트로 확인한다.
- [x] 5.5 외부 HTTP·DB·자격증명 없이 세 입력을 같은 실행기로 가공해 레코드 순서·내용, 격리 건수와 `success`·`partial` 상태를 검증하고 #35 single HTTP·#24 HTTP CSV 실행 없이 테스트가 통과하는지 확인한다.
- [x] 5.6 플러그인 가공 코드 작성, 세 샘플의 데이터 타입·유일키·관계·metadata, 빌드, 실행, 제한·오류·신뢰 경계를 `docs/plugin-development.md`에 문서화하고 문서의 명령을 깨끗한 의존성 설치 환경에서 실행한다.
- [x] 5.7 plugin-sdk·collection-engine 테스트, plugin-config offset·single·CSV 회귀 테스트, 전체 타입 검사·빌드와 OpenSpec strict 검증을 CI와 동일한 명령으로 실행해 모두 통과시킨다.
