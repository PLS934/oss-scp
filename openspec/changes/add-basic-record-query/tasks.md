## 1. 공통 조회 계약

- [ ] 1.1 `platform-db`에 목록 입력·요약·상세·수집 상태와 안정된 조회 오류 타입을 추가하고 단위 테스트로 입력 한도, UUID 검증과 큰 필드 projection을 확인한다.
- [ ] 1.2 PostgreSQL `RecordQuery` adapter에 제한·고정 정렬 목록, 상세와 최신 전체 수집 상태 조회를 구현하고 타입 검사로 드라이버 비종속 공개 계약을 확인한다.

## 2. PostgreSQL 계약 검증

- [ ] 2.1 실제 PostgreSQL fixture로 범위 분리, 기본·최대 크기, 안정적 정렬, 큰 필드 제외와 상세 전체 값 반환을 검증한다.
- [ ] 2.2 실제 PostgreSQL에서 미수집·실행 중·성공·부분 완료·실패 상태와 마지막 저장 시각을 검증한다.
- [ ] 2.3 원천 호출을 실패시키는 spy와 DB 실패 fixture로 원천 독립 조회 및 정제된 `QUERY_FAILED` 오류를 검증한다.

## 3. NestJS 조회 API

- [ ] 3.1 조회 계약을 주입받는 service/controller/module 경계를 추가하고 기존 AppModule 연결 및 타입 검사를 통과시킨다.
- [ ] 3.2 목록·상세 성공, 빈 목록, 400·404·503 오류와 인증 없는 접근을 API 테스트로 검증한다.
- [ ] 3.3 API 테스트에서 조회 요청이 수집·checkpoint·레코드 변경을 호출하지 않는 읽기 전용 동작을 검증한다.

## 4. 문서와 통합 검증

- [ ] 4.1 기본 조회 API의 요청·응답 예시, 목록 한도·큰 필드 제외·수집 상태 범위와 후속 권한 경계를 문서화하고 예시가 계약과 일치하는지 확인한다.
- [ ] 4.2 OpenSpec strict 검증, 변경 패키지 테스트·타입 검사와 저장소 lint를 실행하고 모두 통과하는지 확인한다.
